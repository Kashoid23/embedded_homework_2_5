## Як це працює

### 1. Ідея: вентилятором керує таймер, а не програма

Завдання вимагає трьох речей:
- таймер працює незалежно від циклу;
- немає `delay()`;
- розклад повторюється без участі `loop()`.

Тому ми не рахуємо час у програмі. Апаратний таймер **TIM2** у режимі **PWM** сам формує на піні PA1 сигнал «15 хвилин увімкнено, 45 вимкнено», і так щогодини, нескінченно. Процесор цей сигнал не генерує. Навіть якщо цикл зайнятий або програма зависла, реле продовжить перемикатися.

```
лічильник TIM2: 0 ──────── 15 хв ─────────────────── 1 год → 0 → ...
PA1:            LOW (реле ON)  │  HIGH (реле OFF)            │ LOW ...
```

### 2. Налаштування CubeMX і чому саме такі

#### Тактування: HSE, 100 МГц

Кварц дає точну частоту. На годинному інтервалі похибка внутрішнього генератора (HSI) може набігати до кількох секунд, а з кварцом вона мізерна. Таймер TIM2 отримує 100 МГц.

#### Prescaler = 9999

Таймер рахує такти. Prescaler ділить частоту:

```
100 000 000 Гц / (9999 + 1) = 10 000 Гц  →  1 такт = 0,1 мс
```

Тобто 10 тактів на мілісекунду, це `TICKS_PER_MS` у `fan.c`.

#### Чому TIM2

Скільки тактів займає година:

```
1 год = 3 600 000 мс × 10 = 36 000 000 тактів
```

Звичайний 16-бітний таймер рахує лише до 65 535. TIM2 32-бітний і рахує до 4,29 мільярда, тому година в нього вміщається з запасом.

#### PWM Generation CH2, PWM mode 1

У PWM mode 1 вихід «активний», поки лічильник менший за значення **Pulse**:
- Counter Period (ARR) — довжина всього циклу, 1 година;
- Pulse (CCR) — скільки триває «активна» частина, 15 хвилин.

#### CH Polarity = Low

Модуль реле вмикається **низьким** рівнем. Polarity Low означає, що «активний» стан виходу — це `LOW`. Отже, перші 15 хвилин PA1 = `LOW`, і реле увімкнене.

#### PA1: Alternate Function Open Drain

- **Alternate Function** означає, що пін керується не програмою, а таймером.
- **Open Drain** означає, що пін вміє лише притягнути лінію до GND або відпустити її. Коли PA1 відпускає лінію, модуль сам підтягує IN до своїх 5 В, і реле надійно вимикається. У режимі Push-Pull пін видавав би лише 3,3 В, а для модуля на 5 В цього мало. PA1 витримує 5 В, тому так можна.

#### TIM2 global interrupt

Реле перемикає апаратура, але програмі теж корисно знати, коли це сталося: щоб вести лог і запалити LED. Для цього вмикаємо переривання таймера.

#### PC13 (FAN_LED), Output level High

Вбудований світлодіод на Black Pill світиться від `LOW`. `High` на старті означає, що він вимкнений, поки вентилятор не запрацює.

#### IWDG: Prescaler 64, Reload 4095

Незалежний watchdog. Він працює від окремого генератора LSI (~32 кГц):

```
32 000 / 64 = 500 Гц  →  4096 / 500 ≈ 8 с
```

Якщо програма 8 секунд не «погодує» watchdog, він перезавантажить мікроконтролер.

### 3. Код у `main.c`, по порядку виконання

#### `Includes`
```c
#include "fan.h"
```
Підключаємо наш модуль вентилятора.

#### `PV`
```c
bool watchdogReset = false;
```
Сюди запишемо, чи останнє перезавантаження спричинив watchdog. Це частина логування.

#### `SysInit`
```c
__HAL_DBGMCU_FREEZE_IWDG();
```
Коли дебагер зупиняє програму на паузі чи брейкпоінті, watchdog теж зупиняється. Без цього рядка будь-яка пауза довша за 8 с перезавантажувала б плату під час налагодження.

#### `2`: старт

```c
watchdogReset = __HAL_RCC_GET_FLAG(RCC_FLAG_IWDGRST);
__HAL_RCC_CLEAR_RESET_FLAGS();
```
Мікроконтролер пам'ятає причину останнього перезавантаження. Читаємо прапорець «reset від watchdog», а потім очищаємо прапорці, щоб наступного разу бачити нову причину.

```c
fanStart(&htim2);
```
Запускаємо розклад. Що відбувається всередині, у розділі 4.

#### `WHILE`
```c
HAL_IWDG_Refresh(&hiwdg);
```
Цикл нічого не робить для вентилятора, лише «годує» watchdog. Якщо програма зависне, оновлення припиняться, і через 8 с плата перезавантажиться.

#### `4`: callback-и таймера

```c
void HAL_TIM_PeriodElapsedCallback(...)    → onFanTurnedOn();
```
Викликається, коли лічильник дійшов до кінця і почав з нуля, тобто почалася нова година. Саме в цей момент PA1 сам перейшов у `LOW`.

```c
void HAL_TIM_PWM_PulseFinishedCallback(...) → onFanTurnedOff();
```
Викликається, коли лічильник дорівнює Pulse, тобто минуло 15 хвилин. PA1 сам перейшов у `HIGH`.

Перевірки `htim->Instance == TIM2` і `Channel == ..._2` гарантують, що реагуємо саме на наш таймер і канал.

### 4. Що робить `fan.c`

#### `fanStart()`

```c
if (fanTimer != NULL) {
    return;
}
fanTimer = timer;
```
**Захист від повторного запуску.** Після першого виклику вказівник на таймер уже збережений, і другий виклик нічого не зробить. Без цього повторний запуск скинув би лічильник посеред циклу.

```c
__HAL_TIM_SET_AUTORELOAD(timer, FAN_PERIOD_MS * TICKS_PER_MS - 1u);
__HAL_TIM_SET_COMPARE(timer, TIM_CHANNEL_2, FAN_ON_MS * TICKS_PER_MS);
__HAL_TIM_SET_COUNTER(timer, 0);
```
Записуємо в таймер наш розклад із макросів:
- період: 3 600 000 мс × 10 − 1 = 35 999 999 (мінус 1, бо лічильник рахує від 0);
- імпульс: 900 000 мс × 10 = 9 000 000;
- лічильник ставимо на 0, щоб цикл почався з початку.

Тому значення в CubeMX не важливі: код їх перезаписує. Щоб змінити розклад, досить змінити макроси в `fan.h`.

```c
HAL_TIM_GenerateEvent(timer, TIM_EVENTSOURCE_UPDATE);
```
Нове значення Pulse таймер підхоплює лише на початку наступного циклу. Цей рядок штучно створює «початок циклу», і нові значення застосовуються одразу. Заодно виникає перше переривання «нова година», тож лог і LED одразу показують, що вентилятор працює.

```c
HAL_TIM_Base_Start_IT(timer);
HAL_TIM_PWM_Start_IT(timer, TIM_CHANNEL_2);
```
Запускаємо лічильник, переривання «нова година» і вихід PWM на PA1 з перериванням «імпульс закінчився». З цього моменту таймер працює сам.

#### `onFanTurnedOn()` і `onFanTurnedOff()`

```c
fanIsOn = true;
fanCycles++;
HAL_GPIO_WritePin(FAN_LED_GPIO_Port, FAN_LED_Pin, GPIO_PIN_RESET);
```
- `fanIsOn` — поточний стан, видно в Live Expressions.
- `fanCycles` — скільки разів вентилятор вмикався.
- LED на PC13 дублює стан.

Ці функції **не керують реле**. Реле вже перемкнув таймер, а вони лише відображають подію.

Змінні `volatile`, бо їх змінюють переривання. Компілятор не повинен «запам'ятовувати» їхні старі значення.

### 5. Що відбувається з часом

| Час | Що відбувається |
|---|---|
| 0 с | `fanStart()`: лічильник = 0, PA1 = `LOW`, реле ON, переривання Update → `onFanTurnedOn()`, LED світиться |
| 15 хв | лічильник = Pulse: PA1 сам іде в `HIGH`, реле OFF, переривання CC2 → `onFanTurnedOff()`, LED гасне |
| 1 год | лічильник обнуляється: PA1 знову `LOW`, реле ON, переривання Update → `onFanTurnedOn()` |
| … | повторюється без участі програми |
| завжди | цикл `while` лише оновлює watchdog |

### 6. Як перевірити швидко

У `fan.h`:
```c
#define FAN_PERIOD_MS  8000u
#define FAN_ON_MS      2000u
```
Реле має клацати на 2 с кожні 8 с, LED світитися разом із ним, а `fanCycles` у Live Expressions збільшуватися на 1 кожні 8 с.

## Структура коду

| Файл | Вміст |
|---|---|
| `Core/Inc/Fan.h` | макроси розкладу, оголошення функцій |
| `Core/Src/Fan.c` | запуск таймера, лог, LED |
| `Core/Src/main.c` | ініціалізація, запуск `fanStart(&htim2)`, watchdog, callback-и таймера (блоки `USER CODE`) |

## Запуск

1. Відкрити проєкт у STM32CubeIDE.
2. За потреби поставити короткі часи у `Fan.h`.
3. **Project → Build Project**.
4. **Debug**, потім **Resume**, і додати `fanIsOn`, `fanCycles`, `watchdogReset` у Live Expressions.
